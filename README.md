# Kwast

Пилот мобильной биржи малярных работ в Нидерландах. Интерфейс на русском. Одна компания размещает объект, другая предлагает свою бригаду; одна и та же компания может выступать в обеих ролях.

В приложении два режима, они не смешиваются:

| | Рабочий режим | Демо-режим |
|---|---|---|
| Вход | e-mail и пароль компании | без регистрации, кнопка «Открыть демо-режим» на экране входа |
| Данные | общая база на сервере (`server/`) | только на этом устройстве (`localStorage`, ключ `kwast-pilot-3`) |
| Стороны сделки | разные компании на разных устройствах | переключение демо-компаний на одном устройстве |

Платежей и загрузки документов в этой версии нет. Комиссия 8 % — тестовый расчёт, деньги не списываются. Файл фактуры не отправляется на сервер: сохраняется только отметка «Ожидает проверки». Используйте вымышленные данные, в том числе номер KvK.

## Структура

- `dist/` — интерфейс (HTML/CSS/JS). Один и тот же код работает в браузере, в приложении Android и в приложении iOS.
- `dist/config.js` — адрес сервера, который подставляется на экране входа (`window.KWAST_SERVER`). Если поле пустое, а интерфейс открыт с самого сервера, используется тот же адрес.
- `server/` — сервер на Node.js 22.5+ без внешних зависимостей; база — SQLite (`node:sqlite`).
- `mobile/android`, `mobile/ios` — нативные оболочки (WebView), которые включают `dist` в пакет приложения.

## Сервер

```sh
cd server
npm start                 # http://0.0.0.0:8080, база server/data/kwast.db
PORT=9000 KWAST_DB=/var/lib/kwast/kwast.db npm start
npm test                  # проверки API: права, вместимость бригады, гонка, отмена, перезапуск
npm run e2e               # сделка на двух «телефонах» через интерфейс (нужен Playwright с Chromium)
```

Сервер раздаёт и интерфейс из `dist`, поэтому `http://<адрес>:8080` можно сразу открыть в браузере телефона.

Что проверяет сервер:
- **Права.** Вход по токену сессии: в базе хранится только SHA-256 токена, пароль хранится как scrypt-хэш. Отклик нельзя оставить на собственный объект. Подтвердить бронь и завершение может только заказчик. Отменить бронь — только заказчик или забронированная бригада. Чужие отклики видит только владелец объекта.
- **Вместимость бригады.** При отклике и при подтверждении сервер считает пиковую занятость маляров бригады по дням на даты объекта. Если с новым объектом она превысит размер бригады, бронь отклоняется (HTTP 409) с текстом «На эти даты у бригады свободно N из M маляров…». Проверка и запись брони выполняются в одной транзакции `BEGIN IMMEDIATE`, поэтому из двух одновременных подтверждений одной бригады проходит только одно. Уменьшить бригаду в профиле ниже уже забронированного числа маляров тоже нельзя.
- **Отмена.** Бронь получает статус «отменена» с указанием, кто и когда её отменил. Объект снова открывается, маляры освобождаются на эти даты. История броней видна обеим сторонам.

Для пилота во внешней сети запускайте сервер за HTTPS (обратный прокси с сертификатом, например Caddy или nginx) и копируйте файл базы для резервной копии.

## Как провести сделку на двух телефонах

1. На компьютере в одной Wi-Fi-сети с телефонами выполните `cd server && npm start` и узнайте IP компьютера (например, `192.168.1.20`).
2. Откройте Kwast на обоих телефонах одним из способов:
   - **Без сборки:** в браузере телефона откройте `http://192.168.1.20:8080`.
   - **Приложение Android:** установите отладочную сборку (`app-debug.apk`, см. ниже) и на экране входа укажите адрес сервера `192.168.1.20:8080`.
   - **Приложение iOS:** запустите отладочную сборку из Xcode и введите тот же адрес.
3. **Телефон А:** «Регистрация компании» → название, город, размер бригады, вымышленный KvK, e-mail и пароль. Затем «Разместить объект»: город, даты, описание, число маляров и бюджет.
4. **Телефон Б:** зарегистрируйте другую компанию (например, бригада из 4 маляров). На вкладке «Объекты» нажмите на метку объекта на карте → «Предложить бригаду» → укажите свою цену.
5. **Телефон А:** за 10 секунд отклик появится в открытой карточке объекта («Мои сделки» → объект). Нажмите на название компании Б, чтобы открыть профиль, затем «Забронировать бригаду» → «Подтвердить бронь».
6. Закройте и снова откройте приложение на обоих телефонах. В «Мои сделки → Бронирования» и в карточке объекта у обеих сторон одинаковые даты, цена и статус.
7. **Нехватка маляров:** третья компания публикует объект на пересекающиеся даты, на который нужно больше маляров, чем у Б осталось свободных. Отклик Б не пройдёт. Если два заказчика одновременно подтверждают Б на пересекающиеся даты, одну бронь сервер примет, а вторую отклонит.
8. **Отмена:** любая сторона нажимает «Отменить бронь». На втором телефоне статус «Бронь отменена» появится после автообновления или перезапуска, а Б снова сможет откликаться на эти даты.

Для показа без регистрации нажмите на экране входа «Открыть демо-режим». Вернуться к рабочему аккаунту можно из меню компании: «Войти в рабочий аккаунт».

## Android

Нужны JDK 17+, Android SDK 35 и Gradle 8.9+ (Android Studio подходит).

```sh
cd mobile/android
gradle assembleDebug      # app/build/outputs/apk/debug/app-debug.apk
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

Отладочной сборке разрешён HTTP к пилотному серверу в локальной сети. Релизной (`assembleRelease`) — только HTTPS, а для установки её нужно подписать ключом владельца приложения. В эмуляторе сервер на вашем компьютере доступен по адресу `10.0.2.2:8080`.

## iOS

Откройте `mobile/ios/Kwast.xcodeproj` в Xcode 16 на Mac, выберите схему Kwast и симулятор или устройство с iOS 16+. Чтобы запустить на своём iPhone, выберите свою команду (Apple ID) в Signing & Capabilities. Отладочная сборка (`Kwast/Info-Debug.plist`) разрешает HTTP к серверу в локальной сети, и при первом подключении iOS спросит разрешение на доступ к локальной сети. Релизная сборка работает только с HTTPS-сервером. Папка `dist` включается в пакет при сборке. Сертификата для распространения проект не содержит.

## Браузер

`cd server && npm start`, затем откройте http://localhost:8080. Демо-режим работает и без сервера: `python3 -m http.server 8000 --directory dist`. Для установки веб-приложения на телефон нужен HTTPS.

## Границы пилота

Не реализовано: реальные платежи и платёжный партнёр, загрузка и проверка настоящих фактур, восстановление пароля, push-уведомления (вторая сторона узнаёт об изменениях через автообновление раз в 10 секунд или при возврате в приложение), модерация компаний.
